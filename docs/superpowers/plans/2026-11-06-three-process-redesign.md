# AVideo 三进程拆分实施任务

本文是实施任务与验收记录。勾选代表已完成并通过对应检查。

## 已确认的范围

- Web Server、Event Consumer、Browser Service 独立运行和控制。
- LTX 本阶段关闭。保留历史数据，已有待执行任务挂起，停止生成或执行 LTX 工作。
- 所有浏览器操作默认走持久化异步队列，包括登录检查、打开登录页、影片及女优刮削。
- Browser Service 独占浏览器及 JavDB profile，统一管理冷却、站点限流、登录和人工验证。
- 业务侧只能设置事件优先级，立即任务也遵守浏览器冷却。旧 forced 标记迁移为最高调度档位，不再携带跳过冷却的能力。
- Browser Service 可通过共享领域模块，在实际访问前只读校验影片和任务。
- 刮削、翻译、短标题生成等外部依赖异步执行。其他本地入库、替换、删除、改番号等操作继续同步。
- Consumer 提交外部工作后保存阶段并释放处理能力，通过持久化结果事件恢复工作流。
- Consumer 暂停或停止后，已发出的浏览器命令继续完成并保存结果，待 Consumer 恢复后处理。
- 新增无需登录的 Admin 页面，管理服务、工作流、事件、命令及浏览器冷却参数。
- 继续使用 SQLite。业务结果事件与前端 SSE 进度事件分别存储和确认。

## 基线和执行约束

设计时的代码基线为 main / 7a3b8da，完整测试为 221 项通过。实施开始时重新核对。

工作区包含运行数据库、日志、缓存、封面和实验文件。只提交本计划相关的源代码、测试和文档。
每次涉及切换服务前重新查询进程、任务和浏览器命令状态。部署验证安排在最后一个任务。

## 目标模块边界

以下为建议落点，实施时可以复用现有模块，避免重复队列和重复进程管理逻辑。

| 模块 | 责任 |
| --- | --- |
| core/scrape_queue.py | 保留任务、历史和 SSE 接口，支持新的执行阶段 |
| core/workflows.py | 上传后处理及重新刮削的独立业务流程 |
| core/task_policy.py | 优先级及只读业务有效性检查 |
| core/browser_queue.py | 浏览器命令、尝试、结果事件和领取确认 |
| core/browser_service.py | 浏览器生命周期、访问节奏和命令执行 |
| core/event_consumer.py | 调度工作流、消费结果、业务提交和恢复 |
| core/dependency_executor.py | Consumer 进程内有界执行翻译等外部调用 |
| core/worker_client.py | 非阻塞提交与服务管理，兼容原有调用入口 |
| web/backend/admin_api.py | Admin 查询、控制及设置 API |
| web/templates/admin.html | Admin 页面 |

核心任务流为 Web → 任务 → Consumer → 浏览器命令 → Browser Service → 结果事件 → Consumer。
翻译任务由 Consumer 提交给进程内有界执行器，结果也先持久化再消费。
